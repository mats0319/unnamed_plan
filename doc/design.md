## 架构

前端：Vue3 (html+ts+less)
后端：go
数据库：pg

注：

1. 尽可能少的引入第三方依赖库（例如jwt、protocolBuffer）：为了展示学习成果，尝试自行实现相关功能
2. 尽可能少的引入外部程序（例如redis）：为了维持项目简洁，如需要redis、消息队列等功能，优先尝试使用pg代替

## 功能设计

系统：

- 用户管理系统：注册、登录、查询、修改
    - 最常见的系统，也是配合其他系统
- 小纸条系统：创建、查询、修改、删除
    - 前端总要有点内容展示吧
- 小游戏系统：上传成绩、查询成绩
    - 增加一个展示内容，学习按帧顺序编写程序功能

用户管理系统：

- 注册：填写用户名和密码注册
    - 用户名不能重复
- 登录：填写用户名和密码登录，如果开启了MFA则需要额外输入TOTP Code
    - 暂时只考虑TOTP这一种MFA策略
- 查询：管理员可以查看普通用户
- 修改：包括修改密码、修改TOTP key、启用/禁用MFA
    - 拟做成一个接口，该接口需要显式验证当前密码
    - 修改的输入框为空表示不修改，启用/禁用MFA正常修改
    - 申请新的TOTP key是单独的接口，用户应向程序证明其掌握有根据key正确生成code的能力

小纸条系统：

- 创建：写小纸条
    - 小纸条可选是否公开，不公开的小纸条仅自己和管理员可见
    - 小纸条可选是否匿名，匿名仅前端操作（F12就能查看写条人）
- 查询：不登录也能查询小纸条
- 修改：可以修改小纸条的标题和正文
- 删除：可以删除一个小纸条（软删除）

小游戏系统：

- 上传成绩：未登录时提示：可以正常游玩但是不计入成绩
- 查询成绩：不登录也能查询成绩
